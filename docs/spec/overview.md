# 项目规格

## 项目定位

这是一个个人跨平台工作环境项目，用于定义、安装、部署和移除个人工作环境。

内容包括：

- shell 和终端配置；
- Neovim、WezTerm、pi 等软件配置；
- 自研 CLI、库和插件，以及它们的构建、安装、部署与卸载；
- 软件安装与卸载；
- 持久环境变量；
- 配置部署与撤销；
- 自研项目按需生成资源，并由配置部署机制管理资源产物；
- 仓库自身的工程化配置（作为开发前置条件，不属于工作环境部署流程）。

## 核心能力

```text
软件安装/卸载
自研项目构建、安装、部署与卸载
持久环境变量发布/移除
配置部署/撤销（包括自研项目产物）
多平台适配
项目流程编排
```

## 主要原则

1. 配置内容与配置部署机制分离。
2. 平台差异集中处理，普通声明不重复编写平台逻辑。
3. 每个生命周期模块可独立开发和测试。
4. 每个模块自己负责内部校验、状态和清理。
5. Bootstrap 只负责编排，不实现模块内部流程。
6. 必须提供适用的反操作能力；卸载、回退与清理的执行范围由偏好配置决定，尽力可逆但不承诺完全恢复。
7. 代码质量、可读性和可维护性优先于形式完整。

## 明确非目标

- 不把所有软件配置转换为 TypeScript。
- 不让 Git Hook 修改用户工作环境。
- 不为每个配置文件添加一套独立部署脚本。
- 不自动刷新所有已经运行的应用进程。
- 不为了未来可能的需求提前建立复杂插件 DSL。
- 不从现有实现渐进重构；新实现按 greenfield 开始。

## 主要参与者

```text
配置中心：声明项目目标
Packages：通过平台包管理器管理声明的软件包安装与卸载
Environment：管理声明的环境变量发布、当前流程使用与恢复
Configurations：提供各配置的应用与撤销操作，并提供通用工具和反操作支持
Bootstrap：编排上述三个模块
```

软件配置之间的联动由各软件配置自行定义。跨平台的位置和共享资源通过稳定的环境变量、文件格式或其他共享契约连接；配置不直接依赖其他配置的内部实现。

工程化配置属于仓库的开发前置条件，但不属于工作环境部署领域规格。
