# 设计决策记录

只记录已确认结论，待讨论项见 open-questions.md。

## D001：三个独立生命周期模块

状态：已确认，替代早期四模块方案。

Packages 提供软件包对象及其安装/卸载操作，例如 `packages.neovim.install()`；它决定能够管理哪些软件包，但不提供整体批量编排。Environment 提供环境变量集合级的 attach/get/set/unattach 操作。Configurations 提供配置对象及其 apply/remove 操作。Bootstrap 选择对象、决定顺序并逐项调用；三者互不调用，内部实现不作为外部契约。

取消独立 Resource 模块。构建、打包和生成属于配置应用流程中的可选步骤，不另设资源模块。

## D002：Bootstrap 使用固定三阶段编排模块和配置级操作

状态：已确认，收窄早期直接编排项目命令的方案。

Bootstrap 固定按 Packages → Environment → Configurations 三阶段编排。每个平台 Profile 独立声明各阶段内部对象及其顺序；Bootstrap 逐项启动公开操作并汇总结果。不介入模块内部步骤，不直接逐条执行对象内部命令。

## D003：环境变量是稳定跨平台契约

状态：已确认。

Environment 定义公共变量集合、语义类型、必需性和默认解析规则；平台适配层只解析同一契约的实际值和发布方式；Bootstrap/Profile 可以选择变量或提供经过验证的覆盖值，但不能改变变量集合、类型或语义。必需变量无法解析时必须失败，不允许消费者自行判断平台。

## D004：运行时与部署跨平台分离

状态：已确认。

软件原生配置负责自己的运行时平台逻辑。部署路径、包管理器、环境发布和文件系统差异集中在平台适配层。

## D005：配置中心只声明

状态：已确认。

描述软件、环境契约、配置对象、Profile 选择和阶段内顺序，不执行副作用。Profile 选择内容，平台适配器决定怎么执行。声明格式尚待设计。

## D006：Greenfield

状态：已确认。

不继承旧目录、接口和部署命令；现有代码仅供参考。当前只完善规格，不实现或迁移代码。工程化由用户预先搭建，不纳入当前部署领域设计。

## D007：配置项目自定义应用流程

状态：已确认。

每个配置项目自行定义配置如何应用、步骤顺序、判断和验证。Configurations 登记并暴露这些配置能力，提供通用工具、运行上下文、平台能力、状态记录和反操作支持，但不负责 Profile 选择、项目间排序、整体启动或整体结果汇总。配置项目提供类似 `apply()` / `remove()` 的操作出口，外部编排者负责调用。

## D008：能力与策略分离，尽力可逆

状态：已确认，替代写死自动清理或不清理的结论。

正向动作提供适用反操作，用户偏好决定何时执行及执行范围，包括软件卸载、环境集合恢复和配置清理。不承诺无条件完整恢复。记录所有权与原状态，不误删用户内容，报告不可逆限制及残留。运行时缓存暂不纳入清理范围。

## D009：状态记录与现实状态分离

状态：已确认。

各模块记录操作前状态、本次动作、结果、所有权依据和恢复信息。记录不是现实本身；每次重复部署、更新或移除都必须检查实际状态。没有记录不能自动接管或删除，发现外部修改或无法确认所有权时报告冲突。

## D010：显式项目依赖

状态：已确认。

项目依赖由配置中心显式声明。Bootstrap 根据依赖关系排序，不隐式推断。缺失依赖或循环依赖必须在产生部署副作用前失败。

## D011：模块结果模型保持领域化

状态：已确认。

Packages、Environment、Configurations 不强制共享同一个领域结果枚举。每个模块可以定义适合自身的结果和扩展字段。Bootstrap 只依赖薄层编排信号，例如是否可继续、是否有残留、是否存在可执行反操作；详细结果由模块自己解释、保存和展示。

## D012：取消计划由 Bootstrap 按阶段拥有

状态：已确认。

`install/uninstall`、`attach/unattach` 和 `apply/remove` 是各领域独立的公开操作，不引入统一的 rollback 概念。Bootstrap 根据本次实际执行结果和策略，分别维护 Packages、Environment、Configurations 三个阶段的取消计划。Packages、Environment 和 Configurations 负责领域状态、所有权和被调用操作的安全执行，不决定本次是否取消。

## D013：每个模块使用一个持久化记录文件

状态：已确认。

Packages、Environment 和 Configurations 各自维护一个模块记录文件。该文件可以同时包含当前状态快照和操作历史：当前快照用于重复部署、卸载和所有权判断，操作历史用于失败诊断、未完成检查和后续清理。模块按顺序执行，不设计并发编排；记录写入仍必须具备基本的完整性保护，不能因为进程中断留下无法解析的文件。

## D014：严格停止与取消策略独立

状态：已确认。

只支持严格模式：必要步骤失败后停止后续正向流程。是否回退由策略决定。

正向模块顺序：Packages → Environment → Configurations → 整体验证。
逆向模块顺序：Configurations → Environment → Packages，实际执行范围由策略选择。
