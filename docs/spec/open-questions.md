# 规格制定 Todo

状态：`confirmed` 已确认；`open` 待讨论；`proposed` 建议未确认。规格确认不等于实现验证。

## 已确认基线

- [x] 项目范围：个人跨平台环境，包含外部软件、原生配置、自研工具/插件/库及按需资源。
- [x] 当前只完善规格；greenfield；不开发或迁移代码。
- [x] 工程化由用户预先搭建，不属于本轮部署领域设计。
- [x] 三个模块：Packages / Environment / Configurations；取消 Resource。
- [x] Bootstrap 只编排三个模块及各配置的公开操作。
- [x] 配置中心只声明；Profile 选择内容；平台适配器封装平台差异。
- [x] 三个模块对外提供对象/能力级操作：软件包 install/uninstall，环境变量 attach/get/set/unattach，各配置 apply/remove。
- [x] 每个配置项目自行定义内部应用流程；项目不是独立的基础设施模块。
- [x] Configurations 登记并暴露各配置的应用能力，同时提供工具、运行上下文、平台能力、状态记录和取消操作支持；不负责选择、排序、统筹或汇总整体流程。
- [x] 各配置对外提供独立的应用与撤销操作，外部编排者负责调用。
- [x] 环境变量持久发布，同时供当前流程使用。
- [x] Environment 定义稳定公共变量集合、语义类型和必需性；平台只解析同一契约的实际值。
- [x] Bootstrap/Profile 可选择变量或提供经验证的覆盖值，但不能改变变量集合、类型或语义。
- [x] 必需变量无法在当前平台解析时必须失败，不能让消费者自行判断平台。
- [x] 正向顺序：Packages → Environment → Configurations → 整体验证。
- [x] 逆向顺序：Configurations → Environment → Packages；实际范围由策略选择。
- [x] 只支持严格停止；是否调用反操作由偏好配置决定。
- [x] 正向与反向能力分离于偏好；尽力可逆，不承诺完全恢复。
- [x] 状态和所有权可追踪，安全检查后反操作，报告残留。
- [x] 每次运行 Profile 都重新检查当前状态；已完成且目标仍满足的阶段快速完成并继续，未完成或目标不满足的阶段才执行必要操作。普通重复部署不先卸载；明确重新安装/重新应用时才先执行对应取消操作。
- [x] 状态记录不是现实本身；每次操作都检查实际状态。
- [x] 各模块记录操作前状态、本次动作、结果、所有权依据和可用恢复信息。
- [x] 没有记录不能自动接管或删除；发现外部修改或无法确认所有权时报告冲突。
- [x] 项目依赖必须显式声明；Bootstrap 根据依赖关系排序，不隐式推断。
- [x] 循环依赖或缺失依赖必须在产生部署副作用前报告失败。
- [x] 软件配置自行定义联动，通过共享契约获取资源或能力。

以上是高层基线，不表示下列规格已经完整。

## 待完善规格（不是开发任务）

- [x] 部署项目的通用必备内容：项目身份、依赖、项目步骤、部署内容、语义目标、通用动作、验证、反操作。
- [x] 模块结果模型保持领域化；不强制共享同一枚举，只约定 Bootstrap 所需的最低编排信号。
- [x] 各模块公开生命周期操作只提供 success/failure；成功区分 changed/unchanged，且只有前置条件通过、现实状态验证成功、记录可靠落盘且没有未处理残留/冲突/不确定性时才算 success。详细报告由各模块自己书写和保存，不额外公开 status() 生命周期操作。
- [x] Bootstrap 按 Packages、Environment、Configurations 三个阶段分别维护取消计划；不引入统一 rollback，也不建立跨模块混合取消栈。
- [x] 每个平台独立声明完整 Profile；Profile 使用 TypeScript 表达，并受模块公开对象和参数的类型约束。
- [x] Profile 只选择环境变量并提供语义化输入；Environment 拥有变量定义和默认值解析，不把平台路径字符串直接散落到 Profile。
- [x] Bootstrap 使用固定三阶段：Packages → Environment → Configurations；每个平台 Profile 只声明各阶段内部对象及其顺序，不声明跨阶段全局顺序。
- [ ] 各模块公开操作的具体领域结果、输入上下文和错误边界。
- [ ] 配置声明的具体格式，以及配置操作与通用工具的关联方式。
- [ ] Packages/Configurations 阶段内部的声明顺序约束：哪些对象顺序由 Profile 列表决定，哪些对象需要显式前置条件。
- [ ] 偏好配置边界：策略如何传给模块；不预先替用户选卸载或清理默认值。
- [x] 每个模块使用一个持久化记录文件，同时保存当前状态快照和操作历史；具体字段、文件格式和路径仍待设计。
- [ ] 细化已确认的重复部署/更新能力的验收场景，以及中断后重试与清理失败的行为。
- [ ] 平台支持范围、权限要求和能力不足时如何报告。
- [ ] 语义路径解析与环境发布入口；配置目标和变量共享同一解析结果。
- [ ] 环境变量具体类型、默认值解析、语义化用户输入和覆盖规则。
- [ ] 模块验收场景及跨项目整体验证标准。
- [ ] 用一个抽象配置对象完整走读声明、执行、失败和移除，检验规格一致性。

## 完成标准

- [ ] 关键边界及可观察行为有明确描述。
- [ ] 每个重要正向能力有反操作路径，或明确限制与残留报告要求。
- [ ] 未决项明确标记，不以示例冒充已确认结论。
- [ ] 用户逐阶段审阅；文档之间不存在互相冲突的规则。
- [ ] 后续开发者能够据此实施，无需依赖聊天记录猜测关键行为。
